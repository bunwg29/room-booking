State flow

Rooms load through a typed data-source boundary and React Query. A booking action enters the Zustand store, which rechecks conflicts, requests notification permission, persists the booking, then immediately updates every subscribed screen.

Static room occupancy and active local bookings are combined into derived “Available Now / Occupied” UI states.

Conflict rule

sameRoom && sameDate && newStart < existingEnd && newEnd > existingStart

The rule is applied both when painting disabled slots and again inside addBooking. This second guard prevents stale UI or rapid taps from inserting overlapping reservations.

Booking lifecycle

CONFIRMED
Persist booking, generate pass, schedule reminder.
CHECKED_IN / CANCELLED
Persist transition and cancel scheduled reminder.

5. Technical challenges & resolutions

  1. Reliable conflicts: UI-only disabling can become stale. The interval algorithm is centralized in a service and enforced again at the state boundary.
  2. Cross-platform notifications: native response APIs are not exposed on web. Platform guards preserve the browser demo, while Android/iOS use local date triggers and deep-link into the booking pass.
  3. Offline continuity: Zustand's persistence middleware serializes the minimum booking/session slice to AsyncStorage; denied notifications never invalidate a reservation.
